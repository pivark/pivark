# 升级说明（Community）

目标：**程序文件与数据库平滑升到新版本**，尽量不停业务数据。

## 升级前

1. **整站备份**：数据库 + `data/`（含 `site.env` / `install.lock`）+ `public/uploads/`（及你的上传盘）  
2. 记下当前版本（后台「版本与站点」或 `RELEASE.json`）  
3. 维护窗口通知用户  

## 方式 A：后台在线升级（需授权权益）

若已激活域名授权且含**在线升级**权益：

1. 登录后台 → **运维工具 → 系统升级**  
2. 检查更新 → 下载升级包（`pivark-community-upgrade-*.zip`）  
3. 按向导备份 → 覆盖 → **自动执行数据库迁移**  
4. 升级完成后抽查前台 / 后台 / 关键业务页  

`updates.json` **只指向升级包**，不要用完整 install 包冒充升级源。

## 方式 B：手动升级（开源自用常见）

1. 从 [Releases](https://gitee.com/pivark/pivark/releases) 下载目标版 **upgrade** 包（或按发行说明使用对应包）  
2. 解压到临时目录，核对其 SHA256  
3. **保留不覆盖**：`data/`、用户上传、自定义主题（非 `template/default` 等会被覆盖的路径按发行说明）  
4. 用升级包内文件覆盖内核程序树（`app/`、`vendor/`、`public/static/admin/dist/`、默认主题等，以包说明为准）  
5. **数据库迁移**：  
   - 优先：若包内提供升级迁移脚本 / 后台可触发 migrate，按其执行  
   - 开源手动：按该版本 CHANGELOG / 发行说明中的迁移清单执行；**不要跳版本盲目覆盖**  
6. 清理 `data/runtime/` 缓存后回归测试  

## 数据库如何「平滑」

- 官方升级路径通过**版本化迁移**改表结构，避免手工改库  
- 迁移应可重复、失败可回滚到备份  
- **禁止**在未备份时直接 DROP 业务表  
- 跨多个小版本时：按发行说明逐步升，或使用支持跨版本的官方升级包  

## 升级后检查

- [ ] 版本号已变为目标版  
- [ ] 后台可登录，关键菜单无 5xx  
- [ ] 前台首页 / 列表 / 详情可打开  
- [ ] 支付 / 会员 / 插件等你在用的能力冒烟通过  

## 回滚

用升级前备份还原数据库与文件树；确认 `data/site.env` 与 `install.lock` 完好。
