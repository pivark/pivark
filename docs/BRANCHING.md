# 分支模型（样板 · 对齐主流开源）

> 参考国内成熟开源（如 ShopXO：`master` + `dev` + `vX.Y.Z`）。  
> **外人不要直接往公共集成分支硬推**——Fork 后提 PR。

## 仓库里长期可见的分支（样板）

| 分支 | 属性建议（Gitee） | 干什么 |
|------|-------------------|--------|
| **`master`** | **保护分支** | 默认稳定线；对应最新正式发行（现与 `v1.6.5` / 标签一致） |
| **`dev`** | **保护分支** | 下一版本日常集成；**PR 默认打这里** |
| **`maint/1.6.5`** | **保护分支**（或发版后只读） | **这一版的维护线**（修这个大版本的紧急问题）；不是日常开发区 |

可选同义：`develop` 与 `dev` 当前指向同一集成线（过渡期）；新协作统一用 **`dev`**。

```text
外人：Fork → feature/xxx → PR 合入 dev
维护：dev 稳定后 → 打 tag vX.Y.Z → 更新 master，并拉出维护分支 maint/X.Y.Z（标签仍为 vX.Y.Z）
线上急救：从 maint/X.Y.Z（或 master）拉 hotfix → 合回版本分支 + master + dev
```

## 不要长期留着的

| 名字 | 原因 |
|------|------|
| ~~空壳 `release`~~ | **已删除**（勿再建永久 `release`） |
| 永久空分支 `feature` / `hotfix` | 只是命名前缀，用完即删 |

## 别人怎么交代码（重点）

- **不是**所有人直接 push 到 `dev`。
- 正确姿势：Fork → 自己的 `feature/主题` → 向本仓 **`dev`** 提 PR → Review 后合入。
- `master` / `v*`：**禁止**直推；只接受维护者发版/热修合入。

## Releases 发行页

平台 **Releases** = 下载完整安装包 + 发行说明；与 Git 分支 `v1.6.5`、标签 `v1.6.5` 配合使用，不是第三个「神秘分支」。

## 当前样板指针（1.6.5）

- `master` ≈ 已发布 Community 1.6.5
- `dev` / `develop` ≈ 下一版集成（现同基线，后续只在 `dev` 叠改）
- `maint/1.6.5` ≈ 本版维护线
- 标签 `v1.6.5` ≈ 发行钉扎（与分支分开）

> **Gitee 注意：** 已有标签 `v1.6.5` 时，不能再建同名分支；本版维护线用 **`maint/1.6.5`**（作用等同 ShopXO 的 `v6.9.x` 版本分支）。
